Paksh - project guide for Claude Code

What Paksh is

Paksh (पक्ष) is a live media-bias and transparency platform for Indian news, in English
and Hindi. It groups coverage of the same event across many outlets and shows: a neutral
summary, an arithmetic bias bar (how many distinct outlets on the Left / Centre / Right
covered it), per-side framing, and one-sided/blindspot detection.

Owner: Sameer (product + editorial decisions). Company: Redstocks Technology LLP.
Live at paksh.vercel.app. Future domain: paksh.news.

Sameer is a beginner. Explain changes in plain language. Never assume he'll spot a
subtle breakage - verify your own work and tell him exactly what to check.

THE INVARIANTS - never break these

These ARE the product. If a change cannot preserve all of them, stop and say so.


The bias bar is arithmetic. It counts DISTINCT OUTLETS by publisher lean -
one vote per publisher, never per article, never AI-decided, never weighted.
AI is used for only three things: clustering embeddings, the neutral summary,
and the framing text. It never decides an outlet's lean.
Lean labels belong to publications and are assigned by editors using a fixed
rubric in sources.py. Never auto-generate or guess a lean label.
English + Hindi everywhere, with the working language toggle. Events carry
title/summary and title_hi/summary_hi.
The site stays a static export. No server runtime, no API requirement. It builds
to _site/ and deploys to Vercel as static files.
All data fetches use ABSOLUTE paths (/data/...). Never relative (data/...) -
relative paths break on /story/<id> URLs. This caused a real outage before.
Path routing stays (/, /story/<id>, /topic/<name>, /about, /sources,
/search, /contact, /privacy) via the History API, with crawlable <a href>.
Every story keeps its pre-rendered crawlable HTML page with story-specific title,
meta description, Open Graph tags and NewsArticle JSON-LD, generated by
export_static.py. This is the entire SEO strategy.
Never commit *.db files. paksh.db is huge and breaks git pushes.
Never put API keys in code, files, or chat. Gemini key lives in an environment
variable only.


THE FRAGILE COUPLING (this has broken twice - be careful)

export_static.py builds each story page by splitting static/index.html on two exact
strings:


<div id="root">
<script src="/static/app.js"></script>


(export_static.py precompiles static/app.jsx -> _site/static/app.js at build time; the
shipped page loads the compiled app.js, NOT the JSX source, and NOT Babel.)

If you change the structure of static/index.html (move the mount div, rename app.jsx,
inline the script, add a bundler), you MUST update the split markers in
_story_html() in export_static.py in the same change, or every story page crashes
the export. Always re-run py export_static.py after touching either file.

Tech stack (all currently in use - keep using these)


Frontend: React 18, SELF-HOSTED (pinned, in static/vendor/) - not from a CDN. app.jsx
is precompiled to plain JS (_site/static/app.js) at build time by export_static.py;
no Babel and no JSX ships to the browser. Tailwind is built to static/tailwind.css by
the vendored standalone CLI (no CDN). No npm build step. Files: static/index.html
(shell + SEO head), static/app.jsx (the whole app), static/styles.css.
Database: SQLite, paksh.db (~48k articles, ~2385 events). Accessed via
database.py.
Embeddings/clustering: Ollama running locally, model bge-m3. Must be running
(ollama serve, reachable at http://localhost:11434) for embed/cluster/analyze/
consolidate.
Summaries/framing (LLM): hybrid backend. Top events use local Ollama
llama3.2:3b; overflow goes to Google Gemini gemini-2.5-flash-lite.
Set before running: $env:PAKSH_LLM_BACKEND="hybrid" (otherwise cycles take ~80 min
all-local). Gemini 503 "UNAVAILABLE" errors mean Google is overloaded - the pipeline
correctly falls back to extractive summaries; not a bug.
Hosting: Vercel, static, Root Directory = _site. Config is generated into
_site/vercel.json by export_static.py (clean URLs, SPA fallback, six security
headers).
Deploy method: GitHub Desktop (commit + push). Repo: github.com/Ninjaauraz/paksh.
Vercel auto-deploys from the push. Never use the Vercel CLI.
Contact form: Formspree, endpoint https://formspree.io/f/mkolqann, submitted
with a plain fetch POST (no library - a bundler-free app can't npm install).
Python: Microsoft Store Python, invoked as py (not python).
Project path: C:\paksh_project\paksh (deliberately outside OneDrive - do not
move it back into OneDrive, sync corrupts the database).


The files

Pipeline (Python, project root):


ingest.py - pull articles from sources
gdelt_source.py - GDELT article source (also used for historical backfill)
backfill.py - fetch older/historical news
sources.py - the outlet roster + lean labels (EDITORIAL - see rules above)
database.py - SQLite schema, queries, event shaping, slugify()
cluster.py - embeddings + clustering into events; tuned thresholds
consolidate.py - merge duplicate events (run manually every few days, destructive)
analyze.py - LLM neutral summary + per-side framing + topic/region.
build_prompt uses BALANCED sampling: up to 2 articles guaranteed per covered lean
before filling the rest, so no side is dropped. Do not revert to unbalanced.
recount_migrate.py - recompute bias bars to current rules
cleanup.py - remove junk/grab-bag events (only unambiguous junk; do not add
keyword-spread heuristics, they delete legitimate popular stories)
audit.py - editorial audit report of lean labels
reframe.py - re-analyse ONLY events where a covered side has empty framing;
preserves original created_at; skips rather than overwrites if the LLM is down
refresh.py - one full cycle: ingest -> gdelt -> analyze -> export
live.py - the always-on loop (--deploy --every 180), retries on failure
export_static.py - builds _site/: events.json, per-story JSON, per-story
pre-rendered HTML, vercel.json, robots.txt, sitemap.xml, and RSS feeds (/rss.xml +
one per topic under /rss/<slug>.xml; each item carries the bias line + share card).
SITE_URL at the top is the single place the domain is set.
og_images.py - draws the per-story social share card (1200x630 PNG with the bias
bar) into _site/static/og/<id>.png, generated by export_static.py for the newest
OG_CARD_N events. English-only (matches the English-canonical story page; Pillow
here has no Devanagari shaper). Deterministic output, so unchanged cards don't churn
git. If Pillow/fontTools are missing the build skips cards and keeps the global og.png.


Normal commands

cd C:\paksh_project\paksh
$env:PAKSH_LLM_BACKEND="hybrid"     # before any analyze/refresh/live run
py export_static.py                 # rebuild the site (no Ollama needed)
py refresh.py                       # one full pipeline cycle
py live.py --deploy --every 180     # the auto-refresh loop
py reframe.py                       # dry run; add --apply to actually fix
py consolidate.py                   # dry run; add --apply (destructive, manual only)

Clean rebuild order after destructive changes:
backup paksh.db -> cleanup.py -> consolidate.py --apply ->
recount_migrate.py --apply -> export_static.py -> push.

After ANY frontend or export change, verify


py export_static.py completes with no error.
Home page loads and shows stories with summaries.
Click a story: URL becomes /story/<id>, full summary + bias bar + three framing
cards + a non-zero article list.
Refresh that story page - it must reload the story, not show "All 0" or blank.
Bias bar counts still equal distinct outlets.
Hindi toggle switches titles, summaries and framing.
Mobile width: nothing overflows.
View-source on a story page: story-specific <title>, Open Graph tags, a
NewsArticle JSON-LD block, and the headline + bias breakdown visible in the HTML
body (not an empty <div id="root">).
